# pain001-loader-xlsx Release v0.0.62

**Release Date:** 2026-08-21
**Tag:** v0.0.62
**Python:** 3.10+
**Status:** Stable

## Executive Summary

Benchmark coverage only. No change to the loader: values are normalised
to text and temporal cells refused exactly as in 0.0.61, and the public
surface is unchanged.

The version moves because every member of the `pain001` suite ships the
same number.

## What's new

**Streaming throughput is now measured.** 0.0.61 guarded that
`load_streaming` does not hold every row — the memory property the API
exists for. The other half of the trade was unpinned: streaming should
also cost roughly what a full load costs. It does, at 0.94x, 1.13x and
1.25x across chunk sizes.

The regression that guards against is chunking becoming expensive in its
own right. Re-opening the workbook per chunk would keep every row
correct and leave the memory assertion passing, while making the API
pointless for exactly the large files it exists for.

**Per-cell value normalisation is now measured.** `to_text` runs once
per cell, so it scales with the whole sheet rather than the row count:
~1.67us per cell, roughly 30ms of a ~156ms 2000-row load. Not the
dominant cost — openpyxl's parsing is — but the largest piece this
package actually owns, and the most likely to grow if the formatting
rules get richer.
