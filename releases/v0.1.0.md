# pain001-loader-xlsx Release v0.1.0

**Release Date:** 2026-08-20
**Tag:** v0.1.0
**Python:** 3.10+
**Status:** Stable

## Executive Summary

Two things: a correctness fix in how cell values reach `pain001`, and the
end of a version number that claimed something untrue.

**Values are now text, and date cells are refused.** openpyxl hands back
native Python objects — `float` for numerics, `datetime` for anything
Excel considers temporal. Those were passed straight through, so a
payment amount arrived as `100.0` rather than `"100.00"`, and a
`datetime` arrived where an ISO date string was expected. Values are now
normalised to text with the cell's own number format taken into account,
and temporal cells are rejected with a message naming the offending cell
rather than silently producing a document that fails schema validation
later.

**The version is `0.1.0`, not `0.0.55`.** The previous release was
`0.0.54` while requiring `pain001 >= 0.0.56` — a version claiming to
belong to a release line it predates. The CHANGELOG stated the rule
explicitly ("a `0.0.X` release of this package targets the `0.0.X`
release of `pain001`"), and the metadata contradicted it.

The rule was the wrong one. This package implements the published plugin
contract; it does not wrap the core's surface. A loader fix should not
wait for a core release, and a core release should not force one here.
`0.1.0` steps off the suite-shaped `0.0.X` line so the number stops
implying a coupling that does not exist, and carries the breaking change
above.

## What's in v0.1.0 at a glance

- **Cell values are normalised to text** using the cell's number format,
  so amounts keep their trailing zeros and integers do not arrive as
  floats.
- **Temporal cells are refused** with the cell reference in the error,
  instead of passing a `datetime` into a field that expects a string.
- **Independent versioning, stated plainly.** The CHANGELOG now
  describes what actually binds this package to the core:
  `PAIN001_API_VERSION`, which the registry enforces at load time, and
  the `pain001` floor in `pyproject.toml`. The lockstep members are
  `pain001-mcp` and `pain001-lsp`; see `pain001.suite`.

## Compatibility

`pain001 >= 0.0.56, < 1` is unchanged. Nothing in this release requires
a newer core.

The value change is breaking for any caller that relied on receiving
native Python objects from this loader. Callers feeding rows into
`pain001` are unaffected — text is what it expected all along.
